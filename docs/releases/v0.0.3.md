# Leaf 0.0.3

Long books open at once, webtoons use about half the memory, books carry on
into the next volume, and Leaf now runs on Windows and Linux too.

**Downloads:**

- `Leaf-0.0.3-macos-universal.zip`: Apple Silicon and Intel Macs, macOS 11
  or later. The first time, **right-click → Open** (Leaf isn't signed).
- `Leaf-0.0.3-windows-x64.zip`: Windows, 64-bit. Run Leaf.exe; SmartScreen
  may ask once (**More info → Run anyway**).
- `leaf-0.0.3-linux-x64.tar.gz`: Linux, x86-64.

## What's new

### Reading

- **On to the next volume.** At the end of a book, turning the page opens
  the next book in the same folder (Vol 02 after Vol 01, the next chapter
  of a webtoon), and turning back from the first page opens the one before
  at its end. **Go → Next Book in Folder** (⌘]) and **Previous Book**
  (⌘[) do it directly; `continue_to_next = false` turns it off.
- **Go to Page** (G or ⌘G): type the number, press Return.
- **Magnifier** (Z): a square under the pointer shows the page enlarged,
  from a sharper picture than the one on screen. It costs about 35 MB while
  it's out and nothing once it's put away.
- **Trackpad**: swipe sideways with two fingers to turn the page; pinch out
  to fit a page's width (or bring out the magnifier on two pages), pinch in
  to go back; double-tap with two fingers for the magnifier.
- **Pictures in EPUB novels** get pages of their own where they appear.
  Little ornaments (under 16 KB) don't.

### Faster and lighter

- **Text books are laid out as you read**: the first page now, the rest in
  the background. The title shows `~` before the length until it's known.
  Word files are imported off the main thread, so the window never freezes.
- **Webtoons are held in 512-pixel bands** near the window, not as whole
  strips.

### Telling manga from comics

What the book says now comes before what its pages look like:
ComicInfo.xml's `<Manga>No</Manga>`, its publisher (Viz, Kodansha, Yen
Press... read as manga; Marvel, DC, Image, Dark Horse Comics... as comics;
Webtoon, Tapas, Lezhin... as webtoons), its format and language; an EPUB
that reads right to left; and an issue number like `#012` in the name, as
American comics are numbered. So a black-and-white Western comic with any
of these reads as a comic.

### Customising, with plain files

- **settings.toml**, new, written with every setting commented out: the
  background and accent colours, the progress line, a gap between two
  pages, the webtoon width, how new books are read (`default_mode`), the
  black-and-white threshold, going on to the next book, the magnifier's
  zoom, and the text books' font, size, paper and ink. **Leaf → Edit
  Settings** opens it.
- **keys.toml and settings.toml apply as soon as they're saved**, while
  Leaf is open, with nothing to click. A mistake shows in the title bar and
  the rest still applies.

### Windows and Linux

Leaf now builds and runs on both, with the same reader, keys, settings and
adapters. Windows has the menu bar. Linux reads RAR, 7-Zip and TAR through
the system's libarchive, looked for when the first archive opens, so Leaf
still starts without it. The window needs libxkbcommon (and
libxkbcommon-x11 on X11), which desktops have; the release workflow found
that a bare server without it can't open a window. **PDFs and text books are Mac-only for now**; so
are RAR, 7-Zip and TAR on Windows.

### Built and tested on every push

A GitHub workflow builds every push on Apple Silicon and Intel Macs,
Windows and Linux, runs the tests on each, and checks that each download
really opens a CBZ, a RAR (made with RARLAB's `rar` on Linux), a 7-Zip, a TAR, a
PDF, an RTF, a Word file and a text file (the formats that system reads).
Pushing a version tag publishes the release. `leaf --check <book>` opens a
book without a window, for this and for you.

## Measured

On an Apple Silicon MacBook, release app, Retina window 820×923 pt, against
0.0.2 on the same books:

| | 0.0.2 | 0.0.3 |
|---|---|---|
| A 3.4 MB novel (4,445 pages) on screen | 280–320 ms | 165–200 ms |
| A 1,776-page Word file on screen | 790–830 ms, window frozen | 620–650 ms, window free |
| Webtoon, 2,400-pixel pages: at the top / most while scrolling | 99 / 121 MB | 76 / 97 MB |
| Webtoon, 8,000-pixel pages: at the top / most while scrolling | 217 / 218 MB | 111 / 122 MB |
| Magnifier out / put away | | 119 / 85 MB |
| Idle CPU, novel, manga or webtoon open | 0% | 0% |

What didn't work: making Core Text's layout afresh every 256 pages, to
free the 80 MB or so a long novel holds. It freed nothing and slowed the
first page down, so it's not in. A 3.4 MB novel still uses about 150 MB,
as in 0.0.2.

## Tested

In the packaged app (with a separate config folder): Go to Page; turning
past the last page of Vol 01 into Vol 02, and ⌘[ back to Vol 01's last
page; the magnifier, with a screenshot; webtoon bands, with a screenshot
showing no seams; an EPUB novel with an illustration on its own page;
settings.toml (colours, text paper, ink and size) and keys.toml changed
while Leaf was in the background, and a mistake in settings.toml shown in
the title bar; a 24-point page gap; detection of black-and-white books with
`#001` in the name, `<Manga>No</Manga>`, and an Image Comics publisher (all
comics), and one with none of these (manga). 35 unit tests, including
webtoon bands joining up into exactly the whole page, text laid out as
it's needed, EPUB pictures, ComicInfo publishers, next-volume order, the
settings file and its mistakes, and the config watcher.

Windows and Linux are checked by the release workflow: tests, opening books
with the download, and screenshots of each running.

## Compatibility

Everything from 0.0.2 still works: `state.json`, `keys.toml`, every key
binding, and adapters (protocol 2, unchanged). Books keep their page, mode
and direction. Text books keep their page numbers unless you change their
font or size in settings.toml.
