# Leaf 0.0.4

Every format now opens on every system, Leaf comes for three more kinds of
computer (Arm Windows, Arm Linux and Intel-only Macs), and the first adapter
in the catalog, **Upscale 4K**, upscales pages on the GPU.

**Downloads:**

| System | Download |
|---|---|
| Mac, any (macOS 11 or later) | `Leaf-0.0.4-macos-universal.zip` |
| Mac with Apple Silicon / Intel | `Leaf-0.0.4-macos-arm64.zip` / `-macos-x64.zip` (new: smaller) |
| Windows, x64 / Arm | `Leaf-0.0.4-windows-x64.zip` / `-windows-arm64.zip` (new) |
| Linux, x86-64 / Arm | `leaf-0.0.4-linux-x64.tar.gz` / `-linux-arm64.tar.gz` (new) |
| The Upscale 4K adapter | `upscale-4k-0.1.0-<system>.zip`, one for each |

On a Mac, the first time, **right-click → Open** (Leaf isn't signed). On
Windows, run Leaf.exe; SmartScreen may ask once (**More info → Run
anyway**).

## What's new

### Every format, everywhere

In 0.0.3, PDFs and text books were Mac-only, and Windows couldn't open RAR,
7-Zip or TAR. Now each system reads all of them:

- **PDFs** on Windows and Linux are drawn by pdfium, which ships beside
  Leaf (`pdfium.dll`, `libpdfium.so`) and is loaded only when a PDF opens.
- **Text books** (`.txt`, Markdown, `.rtf`, `.doc`, `.docx`, `.odt`,
  HTML, EPUB novels) are laid out with cosmic-text, as you read, the way
  the Mac does it. They keep their words and paragraphs; bold, italics and
  such are still Mac-only.
- **RAR, 7-Zip and TAR** use Leaf's own readers on Windows, and on Linux
  when the system has no libarchive.
- **Pages** in JPEG XL, JPEG 2000, AVIF, PSD, ICNS, camera RAW (DNG, CR2,
  CR3, NEF, ARW, RAF, ORF, RW2...), TIFF, TGA, EXR and HDR decode on every
  system. HEIC uses the system's decoder: libheif on Linux, the Microsoft
  Store's HEIF extension on Windows.

Old Word `.doc` files are read by a forgiving reader of their own: the
standard one refused the files TextEdit writes, and long ones leave their
last few parts out of the file's own index (Word opens them anyway, and
so does Leaf).

### Six downloads

Arm Windows and Arm Linux are new, and so are Mac downloads for just Apple
Silicon (2.3 MB) or just Intel (2.5 MB), next to the universal one
(3.3 MB). Each is built and checked on its own kind of machine.

### Adapter highlight: Upscale 4K

Leaf scales pages itself, plainly. On a 4K or Retina screen, in full
screen, with a webtoon widened to the window or under the magnifier, pages
are shown much bigger than they were drawn, and line art goes soft. Install
the [Upscale 4K](../../adapters/upscale-4k/) adapter and the GPU does it
instead (Metal on a Mac, DirectX 12 or Vulkan elsewhere):

- **Manga and webtoons** are upscaled in the spirit of Anime4K. Enlarging
  turns an edge into a ramp of grey a few pixels wide; the adapter traces
  that ramp back into a line, keeps dark lines from spreading, and then
  sharpens without halos. The shaders are Leaf's own, written for comic
  pages, not Anime4K's.
- **Colour comics** get the same edge-aware upscale and gentle sharpening
  only, like AMD's FSR 1, so painted colour isn't flattened.
- `upscale_style` in settings.toml picks `lines` or `soft` for every book
  instead.

Leaf never waits for it. Pages show at once with Leaf's own scaling, and
the upscaled ones replace them as they arrive. If the adapter is slow (10
seconds) or fails, Leaf goes back to its own scaler. **View →
Upscale Pages** (U) turns it off and on, and the title bar names the GPU
it's using.

It needs a real GPU. Where the only one is drawn by the CPU (a virtual
machine, Remote Desktop, Windows without its graphics driver), it turns
itself down and Leaf scales as before: on GitHub's runners those took
0.5 to 8 seconds a page, against Leaf's 47 ms.

It's an adapter, not part of Leaf: Leaf stays small (the GPU code would
about double the download), and only people who want it install it. Adapters may now offer
filters like this one (protocol 3; protocol 2 adapters work as before). See
the [catalog](../../adapters/README.md).

## Measured

On an Apple M2, release builds, a 1200×1700 manga page shown at 4K
(2711×3840):

| | Time |
|---|---|
| Leaf's own scaler | 47 ms |
| Upscale 4K, line art, end to end in Leaf | 31–33 ms |
| Upscale 4K, colour, end to end in Leaf | 23 ms |
| A 512-row webtoon band | 5 ms |
| The shaders alone, line art / colour | 13.5–14 / 5.1–5.3 ms |
| The GPU ready, from Leaf starting | about 0.5 s |

The difference between the shaders and the whole is copying the page to
the GPU and back. Pages are handed over in shared memory (mapped files)
both ways, which cut writing a 4K page from 10 ms to 1 ms.

Tried and dropped:

- **Doing the line passes in one shader**, sharing pixels in workgroup
  memory: 20 ms against 13.5 ms. The barriers cost more than the reads.
- **Textures instead of buffers**: no faster, and more code.
- **Stronger retracing** (0.85): crisper, but stair-stepped diagonals. It
  is 0.5 now.

Downloads: the Mac universal zip is 3.3 MB, as in 0.0.3 (the new image
decoders are only in the Windows and Linux builds, since macOS has its
own). The Upscale 4K zip is 3.3 MB.

## Tested

On a Mac: all 12 test books (CBZ, CBR, CB7, CBT, a text PDF, a scanned PDF,
and a novel as TXT, EPUB with a picture, RTF, DOCX, DOC, ODT and HTML) open
with `--check`; the Windows and Linux readers for each are also run on the
Mac in the unit tests, 46 in all. In the app: upscaling on and off with U,
the title bar naming the GPU, and a side-by-side of a page with Leaf's
scaling and with Upscale 4K. The adapter's `--selftest` checks the output
on each GPU: paper stays white, line art comes out at least 30% crisper
than plain enlarging, ink stays within 15% of its weight, the result is
the same every time, and a reply that doesn't write the page is refused.

The release workflow builds every download on its own kind of machine
(Apple Silicon and Intel Macs, x64 and Arm Windows, x64 and Arm Linux),
runs the tests there, opens every test book with the download itself, runs
the adapter's self-test on that machine's GPU (Apple's virtual GPU on the
Mac runners, all passed; software ones on Windows and Linux, all passed,
and turned down when Leaf asks), and takes screenshots on Windows and
Linux.

Not tested: pdfium on this Mac by hand (the workflow tests it on every
system); the trackpad gestures, again; and, rarely (3 times in 40), a
scripted test skipped a page right at launch, which couldn't be made to happen
by hand.

## Compatibility

Everything from 0.0.3 still works: `state.json`, `keys.toml`,
`settings.toml`, every key binding, and adapters (protocol 2 adapters run
unchanged under protocol 3). Books keep their page, mode and direction.
