# Leaf 0.0.5

A small patch: a strength setting for the upscaler, a lighter and faster
Upscale 4K, Leaf in the Linux app menu, and quicker, wider testing.

**Downloads:**

| System | Download |
|---|---|
| Mac, any (macOS 11 or later) | `Leaf-0.0.5-macos-universal.zip` |
| Mac with Apple Silicon / Intel | `Leaf-0.0.5-macos-arm64.zip` / `-macos-x64.zip` |
| Windows, x64 / Arm | `Leaf-0.0.5-windows-x64.zip` / `-windows-arm64.zip` |
| Linux, x86-64 / Arm | `leaf-0.0.5-linux-x64.tar.gz` / `-linux-arm64.tar.gz` |
| The Upscale 4K adapter | `upscale-4k-0.2.0-<system>.zip`, one for each |

On a Mac, the first time, **right-click → Open** (Leaf isn't signed). On
Windows, run Leaf.exe; SmartScreen may ask once (**More info → Run
anyway**). To update Upscale 4K, drop the new zip on Leaf's window: it
replaces the old one.

## What's new

### How hard the upscaler works

`upscale_strength` in settings.toml: `gentle`, `normal` (the default, as
before) or `strong`. For line art, gentle retraces lightly and stays
closest to the scan; strong is crisper still (35% fewer soft pixels along
edges than normal), at the cost of slight stair steps on curves and beads
along hairline diagonals. Each level was looked at side by side, 4×
enlarged: sharpening and thinning harder without retracing harder looked
no different, and retracing past strong snaps edges into steps, so there
are three levels, not a slider. Colour pages get a lighter or stronger
sharpen. A saved change applies at once; the page on screen is made again.

Adapters get the level as `strength` in `page.upscale`; older adapters
ignore it and upscale as they always have, and Upscale 4K treats a request
without it as `normal`, so older Leafs get exactly what they did.

### Upscale 4K 0.2.0: lighter and a little faster

Measured with `footprint` (Activity Monitor's number) while upscaling 4K
pages on an Apple M2:

| | 0.1.0 | 0.2.0 |
|---|---|---|
| The adapter's memory | 187 MB | 148 MB |
| A page, inside the adapter, line art / colour | 20.1 / 10.2–11.5 ms | 17.8–18.1 / 8.1–8.7 ms |
| A page, end to end in Leaf, line art / colour (median of 4) | 34 / 23.3 ms | 32 / 22.5 ms |

On GPUs that share the computer's memory (Apple Silicon, built-in GPUs)
the finished page is now read where the shaders leave it, instead of being
copied into a 42 MB buffer first. The pictures are identical, bit for bit,
for both styles at all three strengths, whole pages and webtoon bands.
Graphics cards with their own memory copy as before.

Leaf itself uses the same memory with upscaling on or off: about 42 MB
for each 4K page it keeps ready (three for a comic, six for two-page
manga).

Tried and dropped: working out the gradients inside the retrace pass,
which would free another 42 MB. It made line art 21% slower (19.4 ms
against 16 ms of shader time), so the gradient pass stays.

The M2 measured 16 ms of line-art shader time today for both 0.1.0 and
0.2.0, against 13.5–14 ms when 0.0.4's numbers were taken, so the
before-and-after numbers above were all taken today, one after another.

### Leaf in the Linux app menu

The Linux download has `install.sh`, `leaf.desktop` and Leaf's icon.
`./install.sh` adds Leaf to your app menu and offers it under **Open
With** for EPUBs, PDFs, zips, images and folders. It opens comic archives
(`.cbz`, `.cbr`, `.cb7`, `.cbt`) in Leaf only where no other app already
does, as on a Mac. Nothing outside your home folder changes;
`./install.sh --remove` undoes it. Leaf's window now names itself `leaf`,
so the desktop matches it to its menu entry, and on X11 it shows Leaf's
icon.

### Testing

- **Installing an adapter zip**: a new test installs a released Upscale 4K
  zip the way a drop on Leaf's window does, then starts it the way Leaf
  does and asks if it's ready. The release workflow runs it on all six
  systems with that system's own zip; it also passed here with the zip
  from the 0.0.4 release.
- **The release workflow takes 10 minutes instead of 26**: it no longer
  times the upscaler on the runners' software GPUs (WARP took 4.6 to 8
  seconds a page), which said nothing about real ones. The Windows jobs
  went from 17–19 minutes to 9, Linux from 7 to 5. The self-test still
  runs on every system.
- On Linux, the workflow installs Leaf into a scratch home folder, checks
  the menu entry with `desktop-file-validate`, checks Leaf became the
  comic default where nothing else was and stayed out where another app
  was, starts Leaf from the menu entry's command, and removes it again.

## Not tested

- Dragging the adapter's zip onto Leaf's window by hand: the drag goes
  through the same code as the test above, but no one dragged it this
  time.
- The Linux menu entry on a real desktop (GNOME, KDE): the workflow checks
  the file and the defaults, not a desktop showing them.
- Upscale 4K on real (not software) Windows and Linux GPUs, and on a
  graphics card with its own memory: the copy-back path there is the same
  as 0.1.0's, but hasn't run on one.

## Compatibility

Everything from 0.0.4 still works: `state.json`, `keys.toml`,
`settings.toml` (the new setting is optional), every key binding, and
adapters (protocol 3, with an optional new parameter). Upscale 4K 0.1.0
works with Leaf 0.0.5, and 0.2.0 with Leaf 0.0.4.
