# Leaf 0.0.2

Leaf now reads almost any book, works out whether it's a manga, a comic or
a webtoon and reads it that way, and follows Folio's safety rules.

**Download:** `Leaf-0.0.2-macos-universal.zip` (3.2 MB), for Apple Silicon
and Intel Macs on macOS 11 or later. Unzip it and move Leaf.app to
Applications. The first time, **right-click → Open**: Leaf isn't signed
with an Apple developer certificate, so macOS asks once.

## What's new

### Reads (nearly) anything

| Format | How |
|---|---|
| RAR, 7-Zip, TAR comics (`.cbr`, `.cb7`, `.cbt`) | macOS's own libarchive |
| PDF | Core Graphics, drawn at the size it's shown, so it's sharp at any window size |
| HEIC, AVIF, JPEG XL, TIFF, PSD, camera RAW, ... | macOS's ImageIO, when Leaf's own decoders can't |
| EPUB | Picture books in the book's own page order (its spine); novels as text |
| Text: `.txt`, Markdown, `.rtf`, Word, OpenDocument, HTML | Laid out into book pages by Core Text |

All of these use what macOS already has, so the download grew by 0.3 MB.
Text pages are fixed, so a book keeps the same page numbers at any window
size.

### Adapts to what you open

- **Manga**: two pages side by side, right to left. The cover stands alone,
  a page that's already a spread stands alone, and **Pair the Cover** (P)
  fixes pairs that are off by one.
- **Comic**: one page at a time, left to right.
- **Webtoon**: one long strip you scroll down, no gaps between pages, held
  to 800 points wide so it isn't blown up on a big screen.

Leaf decides from what the book says (ComicInfo.xml, its name), else from
its first pages: tall, narrow pages make a webtoon, black-and-white pages
make a manga, colour makes a comic. It says what it decided once, in the
title bar, and remembers it. **View** (or 1, 2, 3) changes it; **Two Pages**
(D) turns pairing on or off for any book.

PDFs and text books open as one page at a time, since a PDF of black-and-white
pages can be a manga or a document. View → Manga is one click away.

### Folio's safety, in Leaf

- A crash leaves a report; the next launch says so, and Help → Show Log has
  it.
- **Help → Copy Debug Info** copies what a bug report needs without book
  names, with `~` for your home folder. The log hides it too.
- Adapters built for another kind of computer are refused with a message
  saying so, before anything is installed.
- **Adapters → (adapter) → Remove** moves it to the Trash and forgets its
  approval.
- Untrusted files are checked before they're decoded: images by their
  claimed size (no more than 400 million pixels), archive pages over 256 MB
  are refused, and an adapter message over 96 MB is ignored and logged. The
  log stops growing at 8 MB.

## Fixed

- Two messages arriving together in the title bar no longer hide each other.

## Measured

On an Apple Silicon MacBook, release app, Retina window about 820×1000 pt:

| | |
|---|---|
| Launch to the first page | 130–190 ms for every format below (243 ms for a manga's first open, while it looks at a few pages) |
| Memory, comic / manga / PDF / text | 64 / 75 / 72 / 61 MB |
| Memory, webtoon | 76 MB at the top, about 120 MB while scrolling (each strip is about 30 MB at Retina size) |
| Idle CPU | 0% in every mode |
| Download | 3.2 MB (was 2.9 MB) |

What didn't work at first: preparing five webtoon pages ahead and behind
(165 MB). Leaf now prepares what covers the window plus one more window.

## Tested

Opened in the release build, each with a neutral name so the mode came from
the pages: a black-and-white CBZ (read as manga), a colour CBZ (comic), a
tall-strip CBZ (webtoon), a solid 7-Zip and a TAR (manga), a folder of HEIC
pages (manga), TXT, RTF, DOCX, PDF and text EPUB. Screenshots checked the
manga spread (page 2 on the right), the webtoon strip running from one page
into the next, and a text page. The security features were tested in the
packaged app: crash report, Copy Debug Info, removing an adapter to the
Trash, and refusing a Windows adapter. 26 unit tests pass, including TAR
reading, EPUB spine order, spread pairing, black-and-white detection, a
forged huge PNG, an over-long adapter message, and old `state.json` files.

**Not tested:**

- A real RAR file. There's no RAR tool on this Mac to make one. RAR goes
  through the same libarchive path as the 7-Zip and TAR files that were
  tested.
- The Intel half of the app: it builds and links, but Rosetta isn't
  installed here to run it.

## Known limits

- MOBI/AZW, DjVu and CBA books need an adapter.
- Text EPUBs show their words, not their pictures.
- Detection can be wrong. A black-and-white Western comic reads as manga;
  View → Comic fixes it, and Leaf remembers.
- Opening a text book lays the whole book out first. A 134 KB novel was on
  screen 150 ms after launch in total; much longer books will take longer.
- Mac only for now; the app isn't notarized.

## Compatibility

Everything from 0.0.1 still works: `state.json`, `keys.toml`, every key
binding, and adapters. Books you were reading before keep their page and
direction; Leaf picks a mode for them the first time you open them in
0.0.2. The adapter protocol is now version 2, and only adds things.
